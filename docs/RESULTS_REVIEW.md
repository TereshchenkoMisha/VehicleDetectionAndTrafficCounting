# Проверка результатов и восстановление протокола ablation

Историческая проверка: после неё принята гибридная конфигурация refactor с контролем ablation и детерминизмом. Актуальные настройки описаны в RERUN.md, выбор NMS — в NMS_SELECTION.md.

Проверены основной запуск run_20261102_164923 и завершённый sweep run_20261102_164923_metadata_fixed. Все исходные результаты сохранены. Прерванный ablation_run_20261102_164923 содержит только завершённый GT-этап в manifest и не является полным экспериментом.

## Проверка сохранённых результатов

- Завершённый sweep содержит все 16 условий: YOLOv8n/s × ByteTrack/BoT-SORT × confidence 0.1/0.25/0.4/0.6. Есть все 29 этапов прежнего формата manifest, совпадают хеши всех 118 зарегистрированных файлов.
- Проверены полнота и хеши MOT-файлов, число кадров каждой последовательности и единое записанное окружение.
- Заново рассчитаны события пересечения и MAE/WAPE/SCE для основного запуска и всех 16 условий sweep. Расхождений с отчётами нет.
- Заново рассчитан TrackEval по сохранённым трекам для всех 24 конфигураций: 4 dev + 4 test основного запуска и 16 dev sweep. Совпали per-sequence и combined метрики.
- Во всех четырёх детекторных отчётах число кадров совпало с подготовленными изображениями (1184 dev, 1718 test), хеши весов и ignored regions совпали, mAP находится в допустимом диапазоне. Полный повтор детекторного inference/mAP в рамках аудита не выполнялся.
- Проверены 15 PNG и три выполненных ноутбука: изображения читаются, сохранённых ошибок ячеек нет.
- На confidence 0.25 метрики основного dev-запуска и sweep совпадают.

Эти проверки подтверждают согласованность сохранённых файлов и корректность вычисления метрик по сохранённым предсказаниям. Они не доказывают отсутствие всех методологических ограничений или ошибок детектора.

## Что показывают результаты старого протокола refactor

| Конфигурация, conf=0.25 | Dev MAE | Dev WAPE | Test MAE | Test WAPE |
|---|---:|---:|---:|---:|
| YOLOv8n + ByteTrack | 6.80 | 13.55% | 1.14 | 3.20% |
| YOLOv8n + BoT-SORT | 7.00 | 13.94% | 1.71 | 4.80% |
| YOLOv8s + ByteTrack | 4.20 | 8.37% | 2.29 | 6.40% |
| YOLOv8s + BoT-SORT | 4.20 | 8.37% | 2.14 | 6.00% |

На dev минимальная counting-ошибка у YOLOv8s при confidence 0.25; оба трекера дают MAE 4.2. При confidence 0.6 ошибка YOLOv8n возрастает до 9.6–10.0 машин, у YOLOv8s — до 4.8. Значения mean SCE преимущественно отрицательные: преобладает недосчёт. Вывод о лучшей конфигурации зависит от выбранной метрики и split; 5 dev и 7 test последовательностей недостаточно для уверенного универсального ранжирования.

### Ограничение измерений скорости

При идентичной конфигурации conf=0.25 и одинаковых метриках скорость в основном запуске и sweep различается:

| Конфигурация | Основной dev, FPS | Sweep conf=0.25, FPS |
|---|---:|---:|
| YOLOv8n + ByteTrack | 120.9 | 91.3 |
| YOLOv8n + BoT-SORT | 75.1 | 40.5 |
| YOLOv8s + ByteTrack | 109.4 | 89.4 |
| YOLOv8s + BoT-SORT | 72.8 | 48.4 |

По одним этим данным нельзя определить причину разброса: загрузка системы/GPU, тепловой режим и другие условия нагрузки не записывались. Таблицы скорости вычислены из timing.json корректно, но ускорение при изменении confidence нельзя считать доказанным эффектом порога. Для выводов по скорости нужны повторы в одинаковых условиях, желательно с медианой и разбросом.

Линии test подбирались с использованием test GT; это ограничивает интерпретацию абсолютной test counting-ошибки. Малые количества bus/truck делают их отдельные показатели нестабильными.

## Восстановленная версия

По выбранному пользователем варианту возвращён протокол ветки ablation (4c70b46): --conf задаёт порог детектора, high/new-пороги трекера остаются в YAML (0.25), NMS по классам, детерминированный seed, TF32 отключён. Недостающие возможности возвращены в существующие модули:

- --classes-aware в evaluate_tracking;
- --prepare-gt-only в evaluate_tracking для самостоятельного экспорта GT MOT;
- --preview-only/--preview в prepare_dataset вместо отдельного peek_labels;
- снимки shared/data, проверки XML/ignored regions, инвентаря кадров, весов и готовых выходов;
- lock .running, статус/ошибка эксперимента и безопасное продолжение;
- чтение старых завершённых manifest и analysis_manifest.json для экспортов.

Новых Python-файлов нет. Схема нового manifest имеет version=2 и сохраняет словарь хешей вместо дублирования старой реализации контроллера. Для нового sweep добавлены зарегистрированные этапы снимков входов и GT MOT. Старые manifest читаются без изменения; продолжение незавершённого эксперимента после смены кода/протокола намеренно запрещено.

На реальных первых 100 кадрах MVI_20033 после восстановления сравнили старую ветку и текущий код: YOLOv8n с обоими трекерами при conf=0.1 и 0.6. Во всех четырёх случаях MOT-файлы совпали побайтно (631/637/498/498 строк). Это контрольный прогон, а не полный повтор всех последовательностей и моделей.

Все прежние полные результаты относятся к протоколу, существовавшему до восстановления: class-agnostic NMS и изменение tracker thresholds. Они остаются корректными результатами именно того эксперимента, но не должны выдаваться за результаты восстановленной ветки ablation. Для её полной оценки нужен новый tag и новый прогон; команды — в RERUN.md.
