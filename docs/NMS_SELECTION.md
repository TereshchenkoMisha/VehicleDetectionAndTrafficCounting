# Выбор одного режима NMS и итоговая конфигурация

Выбран NMS по классам: TRACK_AGNOSTIC_NMS=False. В рабочем pipeline нет переключателя NMS и нет второй реализации: используется встроенный NMS Ultralytics с одним зафиксированным значением. Детекторная mAP-оценка также сохраняет стандартный NMS по классам.

## Контрольное сравнение

Два режима сравнены на всех пяти dev-последовательностях (5924 исходных кадра, 251 GT-пересечение): YOLOv8n/s × ByteTrack/BoT-SORT. Test при выборе не использовался.

В обоих режимах одинаковы веса и их хеши, imgsz=960, NMS IoU=0.7, seed=42, детерминированные настройки, ignored regions и линии. Детектор работает с conf=0.1, трекеры — с high/new=0.25 и low=0.1. Для каждого детектора и режима детекции вычислялись один раз и подавались обоим трекерам. Это сравнение точности; FPS из этого эксперимента не используется.

Метод совместной подачи дополнительно проверен на первых 100 кадрах MVI_20033 с YOLOv8n и обоими трекерами: по сравнению с обычным run_tracking совпали все строки MOT и соответствия ID после нормализации номеров. Трекеры используют общий глобальный счётчик ID, поэтому числовые имена ID в совместном запуске отличаются, но порядок идентичностей и ассоциации сохраняются.

Правило выбора зафиксировано до получения результатов: минимальная средняя MAE по всем классам и четырём конфигурациям; при равенстве — средние IDF1 и HOTA. WAPE при одинаковом GT даёт то же ранжирование.

NMS по классам немного лучше по выбранному counting-критерию; общий NMS немного лучше по метрикам трекинга. Поэтому выбор зависит от приоритета проекта. Разница MAE 0.15 соответствует всего трём единицам суммарной абсолютной ошибки по 20 парам «конфигурация × последовательность», а не доказанному универсальному преимуществу. Подсчёт по итогам последовательности допускает компенсацию пропусков и лишних событий. Для более сильных выводов нужны дополнительные dev-последовательности и оценка crossing-event precision/recall.

## Итоговый протокол

- Как в предыдущем refactor: tracker_settings переопределяет high/new значением --conf; detector_conf=min(low, high). При обычном --conf 0.25 детектор сохраняет боксы от 0.1 для второго этапа сопоставления.
- Как в ablation: seed включает детерминизм, один поток OpenCV, отключение TF32; сохранены входные снимки, проверки XML/кадров/весов/хешей, блокировка .running и статусы восстановления.
- Сохранены оценка tracking по классам, диагностические preview, самостоятельный экспорт GT MOT и чтение старых завершённых manifest.
- Один NMS по классам выбран по результатам dev. Альтернативный режим существует только среди артефактов этого сравнения, а не как режим рабочего приложения.

Исполняемый AST семи функций трекинга (tracker_settings, detector_conf, build_tracker, keep_mask, warmup, run_sequence, track_config) совпал с прежним HEAD refactor после исключения docstring и форматирования. Отличия задаются сохранённым детерминизмом в utils и выбранной константой NMS в config.
